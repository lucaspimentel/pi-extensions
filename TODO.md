- [x] Python + pi-tool-permissions integration, step 2.5: auto-mount existing read roots into the sandbox (2026-09-25)
  - Done: the effective read roots (persisted `readAllowPaths` + session grants + scratch roots when `readAllowScratch` is on, i.e. `sessionCfg().readRoots`) are mounted read-only into the python sandbox 1:1 at their host paths, in every mode. Transport: the `tool-permissions:mode` event payload was extended to `{ mode, readRoots }` (one event = full state = one relaunch decision, no debounce needed); emitted from `applyMode`, `session_start`, every read-root grant point (session scratch, session root, persisted project/user grants), and `reload()` when a ctx is available.
  - Collision policy: roots at/under reserved sandbox mounts (`/tmp`, `/workspace`, `/scratch`, `/usr`, `/bin`, `/lib`, `/lib64`, `/sbin`, `/proc`, `/dev`, `/worker.py`) are skipped with a notification; notably `/tmp` never shadows the namespace-private tmpfs. Roots inside the project are skipped (covered by `/workspace`); a root *containing* the project is kept (it grants sibling dirs). Nested roots dedupe to the shallowest. Non-absolute paths and `"/"` are rejected.
  - Filtering lives in `filterMountableReadRoots()` in `extensions/python/sandbox.ts` (exported, unit-tested); `buildBwrapArgs` mounts the pre-filtered roots with `--ro-bind-try` so a vanished root degrades to a missing mount instead of failing startup. `WorkerLaunchSpec.readRoots`, `ControllerOptions.readRoots`, and `StatusReport.readRoots` were added; `renderStatus` and the tool description/prompt guidelines list the mounted roots.
  - Relaunch: eager dispose + single notify on any mode/roots change (reuse of the step-2 pattern); identical events are no-ops.
  - Tests: filter/bind/controller/event cases in `tests/python-unit.test.mts`. Step 3 (audit-hook prompts) now only needs to cover previously-ungranted paths.

- [ ] Python + pi-tool-permissions integration, step 3: permission prompts for out-of-sandbox reads
  - Design settled (grilling session, all decisions below are final; replaces the earlier v1/replay alternatives).
  - Detection (worker): `sys.addaudithook` in `extensions/python/worker.py` installed before user code, hooking `open` + `os.listdir`/`os.scandir` only (no `stat`/existence probes: no prompt storms from glob patterns, and existence probing is the weakest signal). The readable allow-set is derived from `/proc/self/mounts` mountpoints (excluding `/`) at worker startup: the set can never drift from what the kernel enforces, and no protocol change is needed to carry the mount list. Relative paths resolve against cwd; symlinked candidates are realpath'd before the prefix check. Ungranted outside path raises a dedicated exception immediately (fail fast, one path per prompt cycle); the worker returns a new protocol frame `{type:"result", status:"permission_needed", path}` (see `extensions/python/protocol.ts`). Interpreter state is preserved (ordinary exception path).
  - Prompt flow (extension): python emits `tool-permissions:prompt` `{ id, path, suggestedRoot }` and awaits a correlated `tool-permissions:promptResult` `{ id, verdict }` (promise keyed by id, ~30s timeout; timeout or absent listener = deny with an informative error — this also covers non-interactive `print`/`json` mode and `!ctx.hasUI`).
  - Dialog ownership: **tool-permissions renders the dialog** (it captures `ctx` at `session_start`, like python's `lastCtx` pattern), styled after its existing read-root escalation: allow reads from the suggested covering dir (from `suggestReadRoot`) for session / project / user, or deny. Persistence writes `readAllowPaths` via tool-permissions' own config helpers (it owns file paths, legacy fallbacks, merge), then re-broadcasts `{ mode, readRoots }` so the mount flows back through the step-2.5 machinery. Keep the extensions decoupled: the bus round trip is the only contact point.
  - Grant handling: eager sandbox relaunch (state loss, notified; mount stays read-only and kernel-enforced), then **replay-once**: the extension re-executes the stored code + timeout automatically. Safe despite breaking the "code is never replayed" invariant's letter: the relaunch zeroes the old interpreter, so replay runs on a fresh namespace with no double side effects. Document the invariant change in the python README. The prompt/replay loop is unbounded but user-gated: each cycle needs an explicit grant, and replay may surface the next ungranted path.
  - Denials are remembered for the session (python-side set): later attempts at the same path auto-deny with an informative error instead of re-prompting.
  - Audit hook is UX, not a security boundary: kernel mounts remain the enforcement (python README threat model). Add a design doc alongside `extensions/pi-tool-permissions/docs/permission-modes-design.md`.
  - Risk framing: seccomp already blocks all sockets, so an out-of-sandbox read cannot be exfiltrated over the network; the worst case is secrets entering the model context via stdout. Step 2.5 (auto-mounting already-granted read roots) shrinks the set of paths that need this prompt flow to previously-ungranted paths only.
  - Relaunch interactions: step 2.5's dispose-on-event pattern is reused; a grant-triggered relaunch goes through the same single-dispose path, so simultaneous grant/mode changes still restart the sandbox once.
