- [x] Harden `extensions/plan.ts` `isSafeBash` against `find`/`fd` mutating flags. Currently `SAFE_BASH` whitelists any command starting with `find` (`/^\s*find\b/`) or `fd` (`/^\s*fd\b/`) but `DESTRUCTIVE_BASH` has no `find`/`fd`-specific patterns, so `find . -delete`, `find . -exec ./script.sh {} \;`, `fd . -x ./script.sh {}` slip through (existing `\brm\s+/i`, `\bchmod\b/i`, etc. catch common destructive inner commands but not arbitrary user scripts). `pi-tool-permissions` excludes `find` from its auto-allow list for exactly this reason (README ~line 320: "has `-delete` / `-exec` flags").
	- Add to `DESTRUCTIVE_BASH` in `extensions/plan.ts` (~line 21): `/\bfind\b.*\s-(delete|exec|execdir|ok|okdir|fls|fprint|fprint0|fprintf)\b/i` and `/\bfd\b.*(\s-x\b|\s-X\b|\s--exec\b|\s--exec-batch\b)/`. `find` flags are always separate args (never combined like `-rf`), so `\s-FLAG\b` matches reliably; `fd` has no `-delete` so only its exec variants (`-x`/`-X`/`s--exec`/`--exec-batch`) need blocking.
	- Defense-in-depth: existing destructive-command patterns still catch `rm`/`mv`/`chmod` invoked via `-exec`; the new patterns add a backstop so arbitrary `find . -exec ./my-script.sh {} \;` is blocked regardless of the inner command.
	- Keeps `find`/`fd` read-only usefulness during planning (metadata predicates: `-mtime`, `-size`, `-perm`, `-empty`, `-type`, etc. that `grep`/`rg`/`ls`/`read` cannot provide).
